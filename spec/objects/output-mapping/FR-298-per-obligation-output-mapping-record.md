# FR-298: Per-obligation output-mapping record

> BLOCKED-BY QSpec #513: this file still cites the removed `sha256-jcs` / `quire.verification.jcs` identity domain (FR-201); delete that wording when #513 lands.

## Description

When an obligation is requested for output mapping, the mapper SHALL emit
exactly one identity-bearing record that retains its source, dependencies,
target profile, disposition, conditions/causes and generated byte regions.

## Properties

| Property | Description |
| --- | --- |
| `record_id` | Derived `sha256-jcs` identity over `quire.output.mapping-record-identity/v1-draft.1` and the complete key below. |
| `source_obligation` | Exact package/clause identity, digest and FR-203 half-open source region. |
| `source_dependencies` | Ordered semantic/model/type/unit/anchor/capture/clock/history/observation/result selections actually required. |
| `target_profile` | Exact FR-297 value. |
| `disposition` | Exactly one FR-269 member. |
| `conditions` | Ordered typed conditions required for `conditional`; otherwise empty. |
| `causes` | Ordered typed causes explaining unrepresented/refused behavior or other retained facts. |
| `output_regions` | Ordered half-open byte regions in the generated target artifact. Empty for `unrepresented` and `refused`. |
| `adequacy_facts` | Optional separately named observation-adequacy and protocol-adequacy values; never a bare `adequacy`. |

## Identity and comparison

- **Identity kind** — *derived entity*. `record_id` is recomputed from the source
  obligation/dependencies, target profile, disposition, conditions, causes,
  output regions and separately qualified adequacy facts.
- **Key** — every semantic property above except `record_id`. Equality is
  componentwise; display text, filesystem path, timestamp and parser message are
  excluded.
- **Key order** — records follow requested source-obligation order. This order
  is deterministic presentation/assembly order, not severity or causality.
- **Causal order** — source obligation and selected dependencies precede the
  record; generated regions are effects of that exact mapping decision.
- **Absence** — any missing source/profile/disposition member invalidates the
  record. Missing conditions on a conditional record or missing reasons on an
  unrepresented/refused record likewise refuses package assembly.
- **Digest domain** — `sha256-jcs` over the closed identity preimage. Equal
  target text does not merge records for distinct source obligations.

## Invariants

- `preserved`: conditions empty; every required fact represented; at least one
  region unless the profile explicitly maps the obligation to a valid empty form.
- `conditional`: non-empty conditions and generated region(s).
- `unrepresented`: non-empty causes and no output region.
- `refused`: non-empty causes and no substitute output region.
- Each adequacy value names its FR-245 or FR-246 domain. No cross-domain or bare
  value is admitted.

## Acceptance Criteria

| ID | Criteria | Verification |
| --- | --- | --- |
| FR-298-AC-1 | Every requested obligation has exactly one record; omission or duplication refuses package assembly. | Test (TC-150) |
| FR-298-AC-2 | Each disposition satisfies its condition/cause/output-region invariant, and absence never defaults to preserved. | Test (TC-150) |
| FR-298-AC-3 | Mutating any source, dependency, profile, disposition, condition, cause, region or adequacy-domain member changes the derived record identity. | Test (TC-154) |
| FR-298-AC-4 | Equal target bytes do not merge distinct obligations or repair a stale/cross-wired record. | Test (TC-154) |
| FR-298-AC-5 | Observation and protocol adequacy remain separately typed; omission means absent and no bare adequacy is accepted. | Test (TC-150) |
