# Master Requirements Specification

## Composed native Quire language standard

## 1. Purpose

This root indexes the native Quire language requirements. Quire v1 includes state, temporal and protocol/choreography families under one editable source authority. The existing finite-state implementation is a development slice, not the product boundary. The [v1 design](../proposals/quire-v1/README.md) rebaselines the families together before profile-specific implementation resumes. Draft specifications and reviews do not establish implemented capabilities.

## 2. Scope

### 2.1 In Scope

FS01 native grammar and composed profile architecture; FS02 shared model/source and artifact identity; FS03 state semantics; FS04 temporal, clock and observation contracts; the native choreography/protocol and compensation profile; FS05 strict interchange and migration; FS06 output mapping and loss contracts. The [capability matrix](../proposals/quire-v1/capabilities.md) selects bounded v1 subsets and names later capabilities and refusals.

### 2.2 Out of Scope

B's portable method/plan/result implementation, C/D's producer implementations, a duplicate model authority or executable binder, a business workflow execution engine and automatic public publication are outside this repository's implementation ownership. Advanced local projection, realizability and general relational analyses are named later capabilities; their absence does not exclude native choreography from v1. External OCL, FRETish and SysML/KerML forms are output mappings, not editable source frontends.

## 3. System Overview

### 3.1 System Description

The language links state, temporal and choreography clauses through common model types and identities, with explicit semantic profiles and specialized representations/evaluators. The native pipeline preserves source identity through parsing, model linking, validation, evaluation and lowering. A schema package, runtime population and observation trace are distinct subjects. Existing shared-model, IR, temporal and evidence owners retain their boundaries.

### 3.2 Intended Users

Specification authors, model producers, verification operators and toolchain integrators.

## 4. Requirements Architecture

Each stakeholder requirement, story, functional requirement, quality constraint and integration specification is a separate catalog-typed file. Proposal documents remain detailed design inputs; this index does not replace those requirements.

## 5. Requirement Classes

StR states the operational need. US records user intent. FR defines observable behavior. NFR records measurable quality constraints. IT specifies a real external process/API/file boundary. TC and matrix coverage are assessed by the review workflow.

## 6. Requirement Identification

IDs are stable within this repository. Cross-repository identities use ix://agent-ix/quire-specification/ID. Acceptance criteria use the parent ID plus -AC-N; integration steps use -SC-NN.

## 7. Requirement Quality Policy

Requirements use atomic observable outcomes. Unknown support, absent evidence and unimplemented prerequisites remain explicit. Validation of Markdown structure cannot establish semantic correctness or implementation completion.

## 8. State and Execution Model

### 8.1 State Semantics

Runtime inputs are immutable typed finite populations with explicit closure assumptions. Object identity differs from record equality. Optional absence, invalid input and unavailable observation retain distinct meanings.

### 8.2 Transition Semantics

Operation observations belong to one invocation with an authored frame and exact object delta. The required v1 choreography profile composes those contracts with roles, typed messages, choices, parallel branches, bounded repetition and compensation. Its temporal and observation contracts define clocks, captured values, progress and completeness separately from state snapshots.

### 8.3 Determinism Guarantees

Guard and collection evaluation order, source activation and selected canonical domains remain explicit. Resource exhaustion yields incompleteness, not a logical violation.

## 9. Events and Signals

### 9.1 Event Model

The v1 observation contract distinguishes typed domain events, role instances, messages, correlation, clocks, causal ordering and progress. State snapshots and operation captures bind explicitly to those observations. A specification evaluator consumes the records; it does not execute business actions or introduce an application event bus.

### 9.2 Event Guarantees

Only events established by the selected observation binding contribute facts. Closed execution, an open prefix and an incomplete file have different meanings. Incremental monitoring receives explicit progress so silence can discharge or violate a deadline only when the required interval is observable. Missing probes or valuations remain unavailable evidence.

## 10. Error and Failure Model

### 10.1 Error Classification

Invalid syntax/input and unsupported capabilities refuse their stage. Missing observations, cancellation and exhausted resources remain incomplete.

### 10.2 Failure Handling Guarantees

No failed prerequisite yields a completed Boolean. No unsupported obligation is silently erased.

## 11. Traceability

Frontmatter relates StR, US, FR/NFR and IT artifacts. Acceptance-criterion-to-TC coverage and implementation trace tags require the review workflow; existing Rust tests do not automatically create formal TC identities.

## 12. Verification Strategy

Run Quire over this exact repository scope. Use real producers/consumers and independent expected cases for integration evidence. Quire v1 acceptance includes the state workflow, timed refund and branching compensated choreography through executable evaluation, replay and incremental monitoring. Qualification-oriented evidence identifies source, model, binding, implementation and method versions; an observed pass does not itself qualify the system. Existing state tests and authored examples establish only their stated subset.

## 13. Change Management

The user requested /specify and /spec-review for all work. Existing implementation is being specified retrospectively and remains subject to findings. Further dependent implementation waits for the required review and accepted shared contracts. Historical fixture and profile bytes remain immutable under their selected bindings.

## 14. Lifecycle Status

language. [FR-019](functional/FR-019-admit-native-source-profile.md) and the
[versioned amendment](../proposals/native-source-1-draft/README.md) carry forward
its admission rules. The replacement candidate is not enabled by this document;
the adopted historical definitions and their implementation remain distinguishable.

The owner adopted e897f81 for internal implementation. Accepted IR ADR-0054
(PR61, 690bde7) subsequently removed the universal Filament reader prerequisite;
#54 is closed. Generic native compilation can use the existing IR API.
Independent consumer qualification and full FS02/FS03/FS05 acceptance remain
open. FR-017/018 define the versioned amendment resolving B's representational
findings; its tests do not claim B's consumer implementation or adoption.

## 15. Governance Notes

Use private owning issues and isolated worktrees. A integrates the common
standard and native syntax; B owns protocol/results; D model/configuration;
E temporal meaning; F observation/consumer contributions. C continues
engineering-assurance completion. The user distributes the A–F handoffs; no
additional session dispatch is implied. Preserve dependency/template grants.
Standard-wide publication terms remain unresolved.

The [shared foundation](../proposals/quire-v1/shared-foundation.md) is a drafting
checkpoint with artifact reservations and explicit outstanding decisions.
FR-030–049, FR-130, the decomposed FR-020, NFR-010 and their
[planned matrix](composed-foundation/tests.md) establish the shared contribution.
The [grammar](../proposals/quire-v1/shared-grammar.md) and
[state contract](../proposals/quire-v1/state-contract.md) now include ordered
queries/aggregation and explicit anchor, numeric and graph proposals. E's
FR-090–095, NFR-040, IT-040/041 and [temporal matrix](temporal/tests.md) are now
integrated as draft temporal meaning. FR-048 connects the native temporal syntax
and shared predicate environments to that contribution. The full baseline review
has not run and dependent implementation is not authorized by these drafts.
FR-049 and the [choreography surface](../proposals/quire-v1/choreography-surface.md)
now add explicit roles/channels, causal control, compensation stages and typed
cross-instance references to the composed grammar. Exact model/observation and
result-family agreement remain integration work; historical review artifacts do
not review this new scope.

B's [protocol contract](../proposals/quire-v1/protocol-contract.md), FR-050–062,
NFR-020/021, IT-020/021 and [protocol matrix](protocol/tests.md) are integrated
through reviewed PR #19 (`81ec682`), separating decisive truth from subject
closure. F's FR-110–116, NFR-050–052, IT-050/051 and
[observation matrix](observation/tests.md) are integrated through `32c95e9`.
These contributions establish draft obligations and planned cases. The composed
grammar and examples remain proposed; binding interfaces are not fully reconciled
and no new executable coverage is established.
