## Summary

Ticket: QSL-570. PR: quire-specification#300 (private), head 7a61910f0, scoped to `git diff refs/remotes/origin/main...7a61910f0`: one file, FR-408's 'Exact rational bounds' method list. Spec-only. It states the tail rules of terra's EN-4 engine (bounds.rs on qsl-570-impl, PR #1079 head a9a693ac0): the `ln 2` series stops at tail `2^-(71 + b)`, `b` the bit length of `|k|`; the quantile bisects to `2^-65`; the `Φ`, `π` and `1/√(2π)` precision is `2^-(72 + ⌈3u²/4⌉)` capped at `2^-328`; a quantile above 16 is refused as beyond precision. Base review: are the stated tails enough for the `2^-64` claim on `ln`, `π`, `Φ` and the quantile, does the text match the engine, do the FR-408 vectors and TCs still hold, and the owner decision. The text matches bounds.rs: `ln_two(TAIL_BITS + 1 + exponent_bits)`, `QUANTILE_BITS = 65`, `quantile_bits = 70 + min(⌈3u²/4⌉, 256) + 2`, `QUANTILE_CEILING = 16`. Derivations checked. (ln) `2·atanh` with tail `< 2^-70` gives width `< 2^-69`; `ln 2 = 2·atanh(1/3)` with tail `< 2^-(71+b)` has width `< 2^-(70+b)`, and `|k| < 2^b`, so `k·ln 2` adds `< 2^-70`: total `< 3·2^-70`, inside `2^-64`. Under the old fixed rule `k·ln 2` adds `|k|·2^-69`, past `2^-64` once `|k|` is about 32. (Φ width) with precision `B`: Machin's `π` width `< 20·2^-B`; the two roots at scale `2^-B` give `√(2π)` width `< 10·2^-B`; `c = 1/√(2π)` width `< 1.6·2^-B`; with `|Σ| <= 1.26` the `Φ` width is `W < 2.4·2^-B < 2^(2-B)`. (φ) `log2(1/φ(z)) = z²/(2 ln 2) + log2 √(2π) = 0.7213 z² + 1.3257 < 3z²/4 + 2` for every `z`, so `3u²/4` over-covers the Gaussian decay `z²/2` (nats) and `W/φ(u) < 2.4·2^-70 < 2^-68`. (bisection) the upper end keeps `Φ_lower(upper) >= 1 − δ`, so it is at or above `z`; the lower end has `Φ_lower(lower) < 1 − δ`, so `lower − z < W/φ(lower) <= W/φ(u)` (φ falls on `z >= 0`); with the bracket `< 2^-65`, `upper − z < 2^-65 + 2^-68 < 2^-64`. (series) the alternating `Φ` bound holds because the code stops only at `n + 1 >= z²`, past the largest term; for `z < 1` the terms fall from the start, so the spec's 'next term' rule needs no extra start condition. Probes (independent Python re-implementation of bounds.rs, exact `Fraction` arithmetic, truth by a two-sided bisection at 420 bits; script sr-300-tools/bounds_probe.py in the reviewer scratchpad). ln of `1.5·2^k`, width log2, old fixed rule vs new: k=31 -64.21 vs -69.90; k=40 -63.84 vs -70.89; k=200 -61.53 vs -70.18; k=1000 -59.20 vs -70.55; k=-1000 -59.20 vs -70.55, so the old rule misses from about `|k| = 32` and the new rule holds. Φ width at the new precision: u=1 2^-74.59, u=2 2^-76.28, u=4 2^-84.43, u=8 2^-121.51, u=16 2^-263.58, each below `2^(2-B)`; `log2(W/φ(u))` is -72.54, -72.07, -71.56, -74.02, -77.59. Quantile (new rule, old fixed 70-bit rule with a `2^-64` bracket), error of the upper end over `z` in units of `2^-64`: δ=1/100 0.15 vs 0.4; δ=10^-10 0.149 vs 4.02·10^6 (the spec's 'factor near `4 · 10^6`' is this measured miss, not the worst-case bound, which is about 10^8); δ=10^-30 0.051 vs refused (the 70-bit `Φ` bound cannot reach `1 − 10^-30`); δ=10^-57 (z ≈ 15.972) 0.174 vs refused; δ=2^-200 is refused by the new rule (bounds.rs test a_delta_beyond_the_search_ceiling_is_refused); at δ=3/4 the upper end is about 2^-66 while z_{0.25} = −0.6745 (FND-004). Spec-literal variant with the root of `2π` at the `√x` bullet's `2^-70` scale and everything else new: δ=1/100 error 0.15·2^-64; δ=10^-10 error 3.25·10^6 · 2^-64. Gates: `quire validate --scope .` on FR-408 exits 0 on the head and on main with the same output (module duplicate-archetype notices and one `semantic.inline-data-schema` notice, none in FR-408). `cargo test --locked` on the head: 158 passed, 0 failed (backend_provider_v1 11, checked_package_model 4, checked_package_v2 111, model_member_types 22, record_conformance 3, shared_reference 7); no test reads FR-408's bounds. No FR-408 vector changes: AC-2's N values, AC-3's thresholds and AC-12's `n = 11632` use bounds that already sit far inside `2^-64` and TC-355 SC-07 states only the `2^-64` claim, which the new rule meets. quoin 0.28.3, quire 0.36.2 (engine 0.50.2). Owner decision (constants stated vs only the guarantee): the review recommends keeping the constants. FR-408 already states every bound's algorithm to the bit (`2^-70`, `2^140`, Machin, `atanh(1/3)`), and its outward rounding means a bound's exact value can change a decision near a threshold, so two providers that both meet `2^-64` with different tails can disagree on a marginal run. Stating only the guarantee is coherent too, but then the whole method list should become informative and the platform-identity sentence should say 'the same provider'. If the constants stay, FND-001 and FND-002 must be closed so the method is complete. ## Findings

| FND-001 | medium | `1/√(2π)` is not a series: it is `π` through a square root, and the text never says the root's scale deepens. Read literally, the `√x` bullet's `2^-70` scale applies, and the quantile then misses `2^-64` by about `3·10^6` at `δ = 10^-10`. bounds.rs takes both roots of `2π` with `sqrt_at(.., bits)`, the same `2^-(72 + ⌈3u²/4⌉)` scale as the series, not `sqrt`'s fixed `2^-70`. With the root at `2^-70` the `c` width is about `0.3·2^-70` whatever the tails are, so `W/φ` grows with `u`. Probe: error 0.15·2^-64 at δ=1/100 and 3.25·10^6·2^-64 at δ=10^-10. Fix: 'The `Φ` and `π` series stop at the tail bound ..., and the square roots in `1/√(2π)` are taken at the scale `2^-(72 + ⌈3u²/4⌉)`' (integer square root of `⌊2π · 2^(2B)⌋` and its successor, scaled by `2^-B`). | spec/functional/analysis/FR-408-settle-probabilistic-claims-statistically.md:190-202 |
| FND-002 | medium | '`u` is the upper end of the current bracket' does not fix the precision schedule: the bracket's start and growth are unstated, and in the bisection the code keeps the precision of the search's final upper end while a literal reading recomputes it as the upper end shrinks. bounds.rs starts at `[0, 1]`, doubles the upper end (1, 2, 4, 8, 16) until `Φ_lower(upper) >= 1 − δ`, then bisects at midpoints with `c` and the precision fixed at that doubling upper end. FR-408 says only 'bisection over rationals' and ties the precision to 'the current bracket'. Both readings meet `2^-64`, but they evaluate `Φ` at different precision, so they can return different upper ends, and with outward rounding a different `z` can move a regenerative stop by one cycle. Since FR-408 states the constants, state the schedule: start `[0, 1]`, double to at most 16, then halve at the midpoint with the precision of the last doubling's upper end. | spec/functional/analysis/FR-408-settle-probabilistic-claims-statistically.md:190-200 |
| FND-003 | medium | 'refused as beyond precision' names no result, cause or time. FR-408's Outputs require a typed cause, and Admission lists every `unsupported` cause but not this one. The engine returns `StatisticalRefusal::ConfidenceBeyondPrecision` for a regenerative request before any sample is drawn (statistical.rs `check_statistical`). QSL FR-192 settles it `unsupported` with diagnostic `unsupported_projection`/`unsupported-requested-capability`. FR-408 gives a QSpec provider no code to emit. The trigger is also not exactly 'quantile above 16': the engine refuses when `Φ_lower(16) < 1 − δ`, which also takes a `δ` whose quantile is just below 16 (within `W ≈ 2^-262`). Fix: add an Admission bullet, for example 'a regenerative request whose `min(α', β')` is below the lower `Φ` bound's complement at 16 settles `unsupported` with `<cause>`', with the cause named in the FR-409/FR-410 vocabulary. | spec/functional/analysis/FR-408-settle-probabilistic-claims-statistically.md:200-202 |
| FND-004 | low | 'the upper end is used and is within `2^-64` of the quantile' is false for `δ > 1/2`, which FR-407 allows (`0 < α < 1`, `m = 1`): the search starts at 0, so the upper end is about 0 while `z_{1−δ}` is negative. The result is still an upper bound, so the half-width stays outward and no decision is wrong. Only the accuracy claim, here and in AC-7 ('every ... normal quantile is a rational bound within `2^-64`'), fails. Probe: at δ = 3/4 the upper end is about `2^-66` while `z_{0.25} = −0.6745`. Fix: 'for `δ <= 1/2`', or say that a `δ > 1/2` uses the upper bound 0. | spec/functional/analysis/FR-408-settle-probabilistic-claims-statistically.md:193-194 |
| FND-005 | low | The cap `2^-328` never applies: the upper end is at most 16, so `⌈3u²/4⌉ <= 192` and the deepest tail is `2^-264`. The cap mirrors bounds.rs's `extra.min(256)`, which is dead code under `QUANTILE_CEILING = 16`. A reader takes the cap to mean the rule continues above `u ≈ 18.5`, which the 16 ceiling forbids. Fix: drop the cap, or state the deepest tail `2^-264` at `u = 16`. | spec/functional/analysis/FR-408-settle-probabilistic-claims-statistically.md:198-199 |

## Verdict

Not mergeable yet: three medium findings. The core change is right. The new `ln 2` tail and the quantile's `2^-65` bracket with `2^-(72 + ⌈3u²/4⌉)` precision do meet `2^-64`, by derivation and by probe, where the old fixed `2^-70` did not (`|k|` past about 32; δ=10^-10). The text matches bounds.rs. No FR-408 vector or TC needs updating, and the QSpec tests pass. To merge: say the `1/√(2π)` roots take the deep scale (FND-001), state the bracket schedule (FND-002), and give the beyond-precision refusal its result and cause (FND-003). Owner decision: keep the constants (Summary).
