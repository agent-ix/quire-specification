# Spec review of batch B (QSpec)

## Summary

The review covers only the authored changes on PR #630. Changes that came in from `origin/main` merges are out of scope. The review set is `base`, with no analysis lenses. No applicable AssuranceProfile requires an enforced spec-review run for this repository, so this is a direct review.

These claims hold:

- **Values typing agrees with the carried-quantity vocabulary.** FR-414 "Values" refuses a carried value or threshold `ill_typed`/`type-mismatch` before any charge. That matches FR-142 "Carried quantity", where a carried quantity is not an operand of equality or ordering. The text points to FR-142 "Carried quantity sum" for a `sum<N>` collection query over carried values and to `convert<Quantity<u>>(e)` for the exact magnitude. It does not use FR-322's "Carried-quantity sum" wire term where the source rule is meant.
- **Package units and same-name dimensions are consistent.** A package unit `M::ms` keeps its own node (FR-142-AC-19). A source `Time` with no equivalence declared is another dimension than the package `Time` (FR-142-AC-20/21), so `10 ms` and `10 s` of the source units are thresholds of another dimension and refuse `unit-mismatch`.
- **Unit bounds are handled correctly.** "a bounded value `Quantity<u>[min, max]` is read as `Quantity<u>`" agrees with FR-154 "Unit bounds", where the bounded type is a subtype read as `Quantity<u>` and arithmetic yields a plain `Quantity<u>`.
- **The reader rule is placed correctly.** FR-370 step 5 refuses a `value`/`threshold` term typed by a `scalar_type`/`carried_quantity` node at `M/value`. In table order the value is checked before the threshold, so FR-370-AC-19's first-defect expectations hold for the value cases.
- **FR-322 `carried_member`.** The constraint now states an empty `operands` list and a `null` family. The catalog prose ("`carried_member`, which names no operand, and `bound_is_member` over operand 1") reads unambiguously.
- **Renumbering.** The carried-sum criteria are now FR-322-AC-389..391, and TC-187 and the earlier review were renumbered with them. No spec, test or vector file still cites the carried-sum criteria under the old numbers. FR-322-AC-388 is now the case-guard/`related` site-name criterion, and TC-233 verifies it.
- **Every expected numeric value is correct when recomputed:**
  - WA-15 / FR-414-AC-13, latencies `5, 1, 4` of `M::ms` over `past[0, 2]` at position 2:
    - sum `10`, min `1`, max `5`;
    - nearest-rank quantile at q = 1/2 is the ⌈1.5⌉ = 2nd smallest of `1, 4, 5`, which is `4`;
    - `1 M::s` converts exactly to `1000 M::ms`, and `10 <= 1000` is `true`;
    - the filter `> 9 M::ms` keeps no event, so with `min_count 0` the sum is `0`, and `= 0 M::ms` is `true`.
  - WA-16 / FR-414-AC-14: `2, -1, 3` each fit `Int[-5, 5]` with no `outside-domain`, the round trip is exact, the sum is `4 m`, and `4 <= 5` is `true`. `convert<Lc>(5 m)` lies in the carrier.
- **No ceremony was added.** The diff adds no hash, digest, pin or tracking record. The `Cargo.lock` change is an ordinary lockfile update.

The review found four medium and four low findings. Three of the medium findings are about example sources that do not parse under `proposals/quire-v1/shared-grammar.md`. The fourth is a 0-draft claim that has no QSpec source.

| FND-001 | medium | **Unit declarations in the new criteria are not valid under the shared grammar.** `unit-decl = 'unit', ident, ':', qualified-name, '=', exact-number, ['*', qualified-name], ...`, and `exact-number` is only `rational(n, d)` or `decimal(n, s)` (shared-grammar:360-361, 405-406). So `unit s : Time = 1;`, `unit ms : Time = 1/1000 * s;` and `unit m : Length = 1;` do not parse: `1` is a `uint`, and `/` is never rational-literal punctuation (shared-grammar:1341). The paired QSL criteria (QSL FR-194-AC-11/12) write the valid `rational(1, 1)` and `rational(1, 1000) * s`, so the two repos disagree on the spelling of one fixture. This spelling is already widespread (FR-142-AC-19..21, FR-478-AC-10, FR-322-AC-99/104), so the new text follows a convention the grammar does not admit. Fix: write `unit s : Time = rational(1, 1); unit ms : Time = rational(1, 1000) * s;` and `unit m : Length = rational(1, 1);` in FR-414-AC-13/14. Then open a ticket to decide once whether `unit-decl` takes `exact-value` (uint, decimal literal, exact-number), or whether the older examples are respelled. | spec/functional/temporal/FR-414-evaluate-window-aggregates.md:196-197; proposals/quire-v1/shared-grammar.md:360 |

## Verdict

The semantics are sound and every recomputed value is right. The carried-quantity refusal agrees with FR-142, FR-154 and the FR-322 wire rules. Fix FND-001 to FND-004 before merge. Each of them is an example that does not parse under the shared grammar, or a 0-draft claim with no source. FND-001 also makes the QSpec and QSL fixtures diverge. The low findings are ordering, coverage and wording fixes.
