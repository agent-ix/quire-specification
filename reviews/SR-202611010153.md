### Round 1 evidence for FND-001

This same presence/value rule applies to each `QueueGrowthJob` template and `QueueGrowthTransition` in a `queue_growth` witness: all carry the checked value if declared and omit it otherwise. A supplied priority must equal the checked task declaration, and a missing or extra priority is a replay refusal for either carrier.

### Round 1 evidence for FND-002

Run every `identity_cases` row in `proposals/backend-provider-v1/task-priority-vectors.json` through the strict task-transition/queue-growth reader for its named carrier: absent and matching priority under EDF, matching priority under fixed priority, missing declared priority, extra/forged priority, and `priority: null`. Each absent or matching value is accepted; each missing, extra or mismatched value is refused against the checked task declaration; `null` is malformed wire. Apply the same rules to `TaskTransitionIdentity`, `QueueGrowthJob`, and `QueueGrowthTransition`; fixed-priority identities continue to require their checked numeric value.

Run every `order_cases` row in `proposals/backend-provider-v1/task-priority-vectors.json`, including equal deadlines with absent priorities, equal deadlines with declared priorities 9 and 1 and reversed source declaration order, an earlier deadline opposed by priority, same-task activation/occurrence ties, and a fixed-priority control. Repeat the EDF equal-deadline order in a `queue_growth` witness's `ready_order`. EDF selects by earliest absolute deadline, then canonical task name in Unicode scalar value order, authenticated activation transition identity and occurrence. Source declaration order and declared priority do not affect EDF ties. The fixed-priority control orders by checked numeric priority. A queue-growth ready-order mismatch is refused.
