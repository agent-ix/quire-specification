# Common output-mapping contract

Selected identity `quire.output.mapping/v1`, revision `1-draft.1`.

## Subsystem boundaries

The coordinator consumes one strictly read native package, its accepted semantic
profile selections, model bindings from spec artifacts and an explicit
[target profile](../../../spec/objects/output-mapping/FR-297-output-mapping-consumer-profile.md).
It validates the complete request before dispatching each obligation to exactly
one target-profile mapper. The mapper returns one
[per-obligation record](../../../spec/objects/output-mapping/FR-298-per-obligation-output-mapping-record.md).
The coordinator constructs one
[generated package](../../../spec/objects/output-mapping/FR-299-generated-output-package.md)
only after every requested obligation is accounted for.

The common coordinator owns validation, dispatch, record completeness,
deterministic assembly, resource admission and artifact identity. A target mapper
owns only its selected correspondence rules and text bytes. An optional external
parser or tool is an observer of already generated bytes; it cannot call the
mapper, alter the package or establish preservation.

```text
native package + model/semantic selections + explicit request
                              |
                     common coordinator
                              |
              exact target-profile dispatch
                 /            |            \
             OCL 2.4     SysML/KerML     FRETish 3.1
                 \            |            /
           one record per requested obligation
                              |
                 immutable generated package
                              |
             optional structural observer only
```

## Request

The request retains:

- exact source-package reference, source definition/profile selections and
  requested obligation identities in source order;
- model/type/unit/operation/clock bindings from spec artifacts applicable to those
  obligations;
- exact target-profile identity, revision and digest;
- requested output capabilities; and
- byte, obligation, expression-node, nesting, emitted-byte and work limits.

Unknown members, duplicate obligation identities, a source/profile mismatch,
an unsupported required capability or an arithmetic/limit overflow refuses the
whole request before any package bytes are exposed.

## Per-obligation result

Exactly one record retains the source obligation and location; every semantic,
model, anchor, capture, clock, history, observation and result dependency used;
the target profile; the FR-269 disposition; zero or more typed retained
conditions or causes; and zero or more exact byte regions in the generated
artifact. The rules are:

- `preserved` requires representation of every required source fact with no
  retained semantic condition or loss.
- `conditional` requires generated output plus every condition under which the
  claimed correspondence holds. A condition is never silently assumed true.
- `unrepresented` retains the source fact and reason and emits no target region
  purporting to represent it.
- `refused` names invalid intake, profile mismatch, unsupported required
  capability, ambiguous mapping or resource failure and emits no substitute.

An absent record, classification, dependency, condition or required output
region never defaults to `preserved`.

## Package and identities

The generated package contains target bytes, a target-byte `sha256-raw` digest,
the ordered records, the exact request/profile selections, generator identity
and version, and a `sha256-jcs` package identity over
`quire.output.package-identity/v1-draft.1` plus those fields. Output order is the
requested source order with target-profile-defined stable local ordering.
Presentation paths, timestamps, locale, parser results and diagnostic text are
excluded from semantic identity.

External structural observations are separate derived evidence referencing the
immutable package identity and exact observer/tool version. They cannot mutate
the package, record a semantic verdict or become a native source dependency.

## Resource and failure behavior

The coordinator uses checked arithmetic and reserves the complete declared
request/record/output budget before exposing output. Exhaustion or cancellation
returns a typed refusal/incomplete operation result with no partial package.
Source assessment states such as pending or incomplete remain retained source
facts; they never become target Boolean success or a `preserved` mapping merely
because text can be emitted.
