# Historical Quire V1 capability groups and inspected foundations

This 2026-09-10 grouping is retained for decision and evidence history. It is
not the current scope authority because its 51 rows combine independently
deliverable capabilities and inherited exclusions. The current authority is the
[atomic capability inventory](../../docs/v1-capability-inventory.md), owned by
[standard #1](https://github.com/agent-ix/quire-specification/issues/1),
[#9](https://github.com/agent-ix/quire-specification/issues/9) and
[#63](https://github.com/agent-ix/quire-specification/issues/63). Every group ID
below maps to one or more atomic rows; nothing in this historical file may
defer, exclude or close an atomic row.

The historical `V1`, `Later` and `Refuse` labels are superseded. The inventory splits
each group into `Required` product obligations and `Integrity` obligations.
Integrity obligations produce exact typed refusals for unsound claims,
authority violations or prohibited side effects; they are implemented and
tested rather than treated as scope exclusions. A bounded implementation stage
is not permission to remove a required capability from V1.

## Scope audit and long-term architecture

The atomic inventory replaces inherited deferrals with atomic V1 work.
The V1 boundary is chosen by the complete product inventory and semantic
dependencies, not by the operators the current backend happens to implement.

Three independent questions apply to every feature: what its native meaning is,
which language release admits it, and which execution/analysis/export capability
can consume it. A feature can be well-defined and useful for one method even
when another backend refuses it. Unknown syntax is not accepted as an opaque
"supported" extension.

The external family census uses primary sources: [OCL 2.4, §§7 and 11](https://www.omg.org/spec/OCL/2.4/PDF),
[KerML 1.0, §7](https://www.omg.org/spec/KerML/1.0/PDF),
[SysML 2.0 language, §7](https://www.omg.org/spec/SysML/2.0/Language/PDF),
and the [NASA FRET documentation](https://github.com/NASA-SW-VnV/fret/tree/master/fret-electron/docs).
The following Quire choices are design judgments against the program's workflows,
not claims that the current implementation is equivalent to those languages.

| Family being assessed | Complete V1 obligation | Required architectural boundary |
| --- | --- | --- |
| Boolean, value and contract expressions in Quire clauses | Core v1: guards, state assertions, captured amounts and operation conditions depend on them. | One reusable typed predicate layer, with definedness separate from temporal truth and observation availability. |
| Collection queries and transformations | V1 specifies size, membership, count, quantification, filtering, mapping/collect, flattening and exact bounded folds over sequences, sets, bags and ordered sets. | Distinguish container kind, element type, occurrence order, multiplicity and output bounds; collection kinds are never aliases. |
| Tuples, derived values and named query definitions | V1 includes fixed typed records, local bindings, predicates, general pure functions and checked recursion. | Stable declaration/call identities plus explicit purity, effect, termination and resource contracts. Do not make every predicate an untyped string. |
| Type conformance, specialization, subsetting and redefinition | V1 includes explicit model conformance, inheritance, redefinition and dispatch over declarations in spec artifacts, checked by Quire's model view. | Preserve original versus effective declaration identity; refuse ambiguity instead of copying a flattened type with lost provenance. This is Quire's model task, not a reason to fork the type system. |
| Associations, references and containment | V1 includes explicit graph semantics and recursive value containment under explicit bounds. | Keep object identity, links, containment and universe closure distinct; model navigation does not become ambient lookup. |
| Parts, ports, interfaces, connections and allocations | V1 consumes these as typed participant/channel/payload/component references declared in spec artifacts. | Maintain role, component, endpoint, channel, build and deployment identities independently; consuming complete model meaning does not make an external notation a second clause language. |
| Actions, state transitions, control/data flow | V1 includes action structure, choice, concurrency, iteration and model-based execution consumers. | Distinct behavior nodes and event contracts, with typed state predicates attached to actions and transitions; external effects remain behind authorized adapters. |
| Temporal scopes, triggers, response windows and history | V1 requires explicit scope boundaries, captured triggers, bounded future/past obligations and deadlines. | A clock/history/completeness contract must precede surface shorthand and lowering; do not equate end-of-file with execution closure. |
| Physical quantities and dimensional models | V1 includes exact units, conversions and explicitly modeled continuous/hybrid dynamics. | Value representation, dimension, unit and conversion rules stay separate. A duration cannot silently become an event count. |
| Requirements, assumptions, verification links and evidence | Native obligations bind to existing requirement identities and evidence contracts in v1. | Preserve semantic subject versus verification method versus result. Do not make a clause-language feature responsible for Quoin's assurance store. |
| General local projection, refinement, realizability and hyperproperties | V1 includes each as an independently requested method with explicit premises and counterexamples. | Retain owners, assumptions, visibility, trace identities and derivation edges. An analyzer must not require reauthoring the choreography or rewriting historical evidence. |
| Model metadata, views, rendering, tool APIs and library ecosystems | V1 includes typed metadata/view/rendering APIs, lossless source tooling, extension contracts and reusable libraries. | Versioned model/package interfaces and output mappings; no foreign-runtime semantic dependency hidden in an adapter. |

Effort decisions belong at feature-family and consumer boundaries. Exact type,
identity, time, event, composition, tooling and analysis contracts are costly to
retrofit and are specified together up front. Delivery may proceed through
dependency-ordered tickets only after every capability is specified and owned.
No calendar or staffing estimate is invented from these classifications. Each implementation ticket must expose its actual
dependencies and a useful independently assessable result.

## Design consequences and retained decisions

The normative specification must cover all V1 rows together before dependent
implementation. The owner-approved ticket plan is recorded in the existing ecosystem
roadmap; detailed task acceptance consumes the reviewed baseline. V1-017 is a deliberate proposal to admit a separately named
graph facet in the wider language; it is not a claim that the previous ruling
already admitted object equality or closure. The original minimum-only
`ConfigVersion` remains an explicit design gate under V1-011. Neither removing
its parent relationship nor manufacturing an integer maximum closes that gate.

The temporal bridge must retain separate native, TL, clock and observation
profile identities. Existing closed TL semantics may extend false propositions
beyond closure; native finite/end-of-execution semantics must select that rule
explicitly or use a different profile. Backend acceptance is not correspondence.

The implementation plan must expose every missing atomic capability, including
numeric, collection, model, temporal, observation, protocol, analysis,
workflow, tooling, mapping and composition work. It must not use a green bounded
suite to mark a broader row delivered.
